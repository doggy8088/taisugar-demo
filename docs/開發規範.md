# 物業管理系統開發規範

此規範將前次需求訪談的所有問題轉為開發決策。第一階段交付可在本機操作的 ASP.NET Core MVC 網站。需要外部服務、法定帳務或正式身分管理的項目，明確安排於後續階段。

**產品目的**

集中維護土地以外的出租資產，連結出租單位、承租戶、租約、水電與帳款，讓管理人員查看出租現況及租金收取情形。畫面使用繁體中文，預設時區為 Asia/Taipei、幣別為新台幣。

**48 項需求決策**

| 編號 | 主題 | 決策及交付範圍 |
| --- | --- | --- |
| 1 | 資產種類 | 商辦、店面、住宅、倉庫、停車場及其他；土地不納入。設備可先分類為其他，專用設備履歷後續再做。 |
| 2 | 出租方式 | 採資產與出租單位兩層結構。整棟出租也建立一個代表整棟的單位。 |
| 3 | 一約多標的 | 第一階段一份租約對應一個出租單位。多單位分別建約，以免模糊租金分配。 |
| 4 | 共同出租 | 同一單位同一期間只能有一份有效租約；多人共同承租先指定一位主要承租人。 |
| 5 | 公司與部門 | 單一企業使用，資產可填所屬公司／分支名稱。多租戶隔離及多法人合併報表列後續階段。 |
| 6 | 租金收入定義 | 分開顯示應收與實收；不將未收租金視為已收到款項。 |
| 7 | 第一階段帳務 | 包含應收、分次收款及未收餘額。 |
| 8 | 水電範圍 | 包含表號、戶號、單價、讀數與費用計算。水電費轉應收由人員確認後手動建立。 |
| 9 | 繳款週期 | 每月計費，繳款日為每月 1～28 日。季繳、年繳、日租列後續階段。 |
| 10 | 不足月與免租 | 按當月實際天數比例計租，起訖日皆計入；免租期與優惠折讓列後續階段。 |
| 11 | 舊資料匯入 | 第一階段手動建檔並提供範例資料；正式 Excel 匯入待來源格式固定後實作。 |
| 12 | 技術與部署 | .NET 10、ASP.NET Core MVC、EF Core、SQLite。本機啟動；正式多人部署另評估 SQL Server。 |
| 13 | 分類與編號 | 面積統一使用坪；編號由人員輸入，同模組不得重複；記錄資產管理人及公司名稱。 |
| 14 | 資產狀態 | 資產支援啟用、維修中、停用；出租單位另支援自用。出租中與空置中由租約推算。 |
| 15 | 附件 | 照片、平面圖、權狀及合約附件列後續階段，第一階段不接收檔案。 |
| 16 | 承租對象 | 支援公司與個人，一位主要聯絡人；多聯絡人及保證人列後續階段。 |
| 17 | 敏感欄位 | 公司可填統一編號；第一階段不蒐集身分證字號及銀行帳戶。 |
| 18 | 資料留存 | 有交易關聯的主檔保留，透過停用管理；正式留存年限與刪除程序於登入／權限階段設定。 |
| 19 | 租約狀態 | 草稿、有效、已終止；有效租約超過到期日後自然不計入當日出租率。 |
| 20 | 續約 | 建立新租約，保留舊約；租期不得與其他有效租約重疊。 |
| 21 | 調租 | 第一階段單份租約固定月租；已出帳租約不可直接變更計費條件，階梯式租金後續支援。 |
| 22 | 稅額 | 使用者輸入最終應收金額，系統不自動拆稅或推算法定扣繳。電子發票與稅務計算列後續。 |
| 23 | 其他費用 | 應收支援租金、水費、電費、管理費、其他；非租金費用手動建立。 |
| 24 | 押金 | 在租約獨立記錄約定押金，不計入租金收入。押金實收、退還與扣抵帳務列後續階段。 |
| 25 | 提前解約 | 可將租約設為已終止；既有帳款保留，不自動重算退款或違約金。提前終止日、結清流程列後續。 |
| 26 | 逾期 | 到期日隔日起算逾期，不自動假日順延、不計利息或滯納金。 |
| 27 | 水電付款方 | 首版以公司代收情境建模；承租戶自行繳付者可只維護表資料，不建立應收。 |
| 28 | 水電表結構 | 每個表屬於一個出租單位，一個單位可有多個表；公共總表與分表階層列後續。 |
| 29 | 水電費率 | 固定單價乘以實際用量；當期單價保存在抄表紀錄，之後修改主檔單價不回寫既有抄表。 |
| 30 | 公共費用 | 第一階段不自動分攤；管理人員依公司核定結果建立各單位應收。 |
| 31 | 尾差與基本費 | 金額按元四捨五入；基本費及分攤尾差暫由人員確認並納入應收。 |
| 32 | 換表與估算 | 換表建立新表號；讀數不得倒退。不自動估算漏抄或跨租戶用量。 |
| 33 | 出帳方式 | 管理人員選定月份後按下產生租金應收；不做無人確認的排程出帳。 |
| 34 | 預收與分次款 | 支援一張帳款多筆收款。預付款須先有對應帳款；一筆匯款跨期請分筆登錄。不接受超額收款。 |
| 35 | 收款方式 | 銀行轉帳、現金、支票、其他，保留交易參考號；不串接銀行。 |
| 36 | 帳務更正 | 無收款的應收可更正或作廢；有收款關聯的應收鎖定金額與歸屬。收款金額與歸屬不可改寫，須作廢原筆後新增。正式退款、折讓、呆帳與關帳列後續。 |
| 37 | 出租率 | 分母是啟用資產下的啟用單位數，分子是指定日期被有效租約占用的單位數。維修、自用、停用排除。 |
| 38 | 報表分類 | 首版提供全公司月度應收／實收及六個月趨勢；公司、區域及多維交叉報表列後續。 |
| 39 | 預警與歷史 | 首版提供目前逾期款項及未來 90 天到期租約。月份出租率由現存主檔與租約重算，不宣稱是不可變的歷史快照。 |
| 40 | 匯出格式 | Excel、CSV、PDF 與固定格式列印列後續階段，首版以畫面列表及圖表數據表查詢。 |
| 41 | 使用裝置 | 桌面為主，支援手機；表格在窄螢幕內橫向捲動。多人修改以版本識別避免覆寫。 |
| 42 | 誤刪復原 | 刪除前確認，僅無關聯主檔可實體刪除；不提供資源回收筒，復原依備份。 |
| 43 | 登入角色 | 第一階段不登入。後續設系統管理員、物業人員、財務人員及唯讀人員。 |
| 44 | 通知 | 首版使用首頁待辦資訊，不寄 Email、不接 LINE；外部通知後續實作。 |
| 45 | 外部串接 | 會計、銀行與電子發票均列後續，不預先傳送資料至第三方。 |
| 46 | 備份 | 正式部署目標為每日備份、至少保留 30 天，預計 RPO 24 小時、RTO 4 小時。首版提供離線備份操作說明，尚未建立自動排程。 |
| 47 | 維修與支出 | 修繕工單、點交、設備履歷與成本支出列第二階段；首版僅維護維修中狀態。 |
| 48 | 驗收與時程 | 首版以本文件功能及整合驗收為交付範圍，不承諾尚未排程的後續功能完成日期。由使用者最終驗收，AI 先完成本機自動及瀏覽器測試。 |

**資料與關聯**

- `Asset`：編號、名稱、分類、地址、公司、管理人、面積、狀態、備註。
- `Unit`：所屬資產、編號、名稱、樓層／位置、面積、狀態、備註。
- `Tenant`：編號、名稱、公司／個人、統一編號、聯絡人、電話、信箱、地址、狀態、備註。
- `Lease`：所屬單位、承租戶、租期、月租、約定押金、繳款日、狀態。
- `Meter`：所屬單位、表號（編號）、戶號、表類型、單價、狀態。
- `Reading`：水電表、抄表日期、前次讀數、本次讀數、本期單價、計算費用、狀態。
- `Invoice`：租約、費用類型、所屬月份、繳款期限、應收金額、狀態。
- `Payment`：應收帳款、實收日期、金額、方式、交易參考號、狀態。
- 每類資料包含獨立識別碼、更新時間及並行編輯版本；未建立操作者身分及完整操作稽核軌跡。

資料庫外鍵限制關聯刪除；每個模組的編號唯一。租約、月份、費用類型的組合唯一。水電表、抄表日期的組合唯一。未來若同月同類費用需多筆，必須先擴充計費期別模型，不能移除唯一限制而失去重複出帳保護。

**計算規則**

月租按以下公式處理：

`本月應收租金 = 月租 × 本月租用天數 ÷ 本月總天數`

起訖日皆計入。結果使用 AwayFromZero 四捨五入至整數元。例如 1 月 16 日起租、月租 31,000 元，1 月租用 16 天，應收 16,000 元。

`水電用量 = 本次讀數 − 前次讀數`

`水電費用 = 水電用量 × 本期單價`

費用四捨五入至整數元。例如用量 10.5 度、單價 5.5 元，費用為 58 元。前次讀數由管理人員依紀錄填入，系統不自動推算抄表銜接關係。

`未收餘額 = 有效應收金額 − 有效收款合計`

作廢收款不計入實收。作廢應收不計入應收合計。押金不計入租金收入。應收按帳款所屬月份統計，實收按實際收款日期統計；兩者口徑不同，不以差額直接推導當月欠款。

租金、押金、應收及收款以整數元輸入。面積、讀數與單價最多兩位小數。所有 decimal 欄位在 SQLite 以放大 100 倍的整數保存，避免二進位浮點誤差。輸入值及計算後費用上限為 999,999,999。

**畫面與查詢**

- 清單提供編號、名稱及備註搜尋；搜尋不含地址、聯絡電話或關聯資料名稱，畫面明確提示搜尋範圍。
- 狀態篩選、編號／名稱／最近更新排序。
- 預設每頁 10 筆，可選 20、50 筆；以 SQL `Skip`／`Take` 分頁。
- 超出範圍的頁碼自動調整至有效頁碼，空清單顯示明確提示。
- 編輯畫面有標籤、必填標記、伺服器驗證及錯誤摘要。關聯欄位使用下拉選單。
- 已有關聯的主檔不允許刪除。應收、收款及抄表保留歷史，刪除操作提示改用作廢或停用。
- 以桌面資料密度為主，手機支援導覽切換、單欄表單及表格內橫向捲動。

**工程規範**

- 維持 ASP.NET Core MVC 的 Controller、Service、Model、View 分工。
- 新模組必須明確註冊可輸入欄位，不得直接以任意表單欄位更新整個實體。
- 所有寫入使用 POST，驗證防偽權杖；查詢使用 GET。
- 後端驗證為最終依據，不能只依賴 HTML 欄位限制。
- 使用交易與唯一索引避免重複帳款；編輯檢查版本，避免舊表單覆寫新資料。
- 計算規則放在 Service，不在 View 重複實作。
- 新的財務或關聯規則應加入整合驗收；純視覺修改以瀏覽器檢查。
- 修改資料庫 schema 前加入 migration 與升級測試；不可直接刪除正式資料。
- 不將 SQLite 檔案、密碼、建置產物、驗收截圖納入 Git。
- 每完成一項功能或修正，提交獨立 Git commit。標題及內文使用繁體中文，內容須涵蓋變更、業務規則、驗證方式及未完成事項。

**首版限制與後續工作**

首版是具備資料持久化與帳務驗證的本機管理網站，尚未整合登入權限、附件、通知、匯入匯出、法定會計、押金交易與自動備份。提前終止與稅務退款不自動計算。若需要正式營運，優先完成身分與權限、稽核紀錄、資料庫遷移、備份還原演練及帳務更正流程，再開放網路存取。
