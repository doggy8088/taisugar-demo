# OWASP Top 10 安全檢核

將實際安全控制與 OWASP 風險類別逐項對照。預設只讀檢查；使用者要求修正時才修改程式碼。

## 範圍與版本

- 先讀專案 `AGENTS.md` 及適用的安全政策。依使用者要求檢核整個專案、特定功能或 Git 差異；差異檢核仍須追蹤必要的呼叫端、共用控制與資料流。
- 未指定版本時採用 **OWASP Top 10:2025**，在報告列出版本，讀取 [2025 檢核參考](references/top10-2025.md)。指定其他版本時，查閱該版 OWASP 官方分類後再對照，不能混用編號。
- 此專案的檢查入口與驗證方式見 [專案檢核參考](references/project.md)。先確認目前檔案與行為，文件敘述不等於實作證據。
- 可直接進行本機原始碼、設定及既有測試的檢查。動態驗證使用隔離環境與合成資料；對外服務的主動測試須有明確目標與授權。範圍不明時先完成靜態檢查，列出動態驗證缺口。

## 執行方式

1. **建立檢核地圖。** 記錄版本或提交、範圍、登入與授權邊界、敏感資料、資料存取、外部服務、套件及部署設定。確認驗證命令與測試隔離方式。
2. **逐類追蹤證據。** 依參考涵蓋十類風險。搜尋只用來找入口；對候選問題追蹤「可控輸入 → 驗證／授權 → 敏感操作 → 可觀察影響」，並檢查全域中介軟體、框架預設與反向代理等補償控制。
3. **驗證與排除誤報。** 優先用原始碼與既有隔離測試驗證。需要重現時採最小、可清理的測試；保留命令、結果與限制。無法執行時標記未驗證，不能聲稱已重現。相同根因的多個入口合併成一項發現。
4. **評估影響。** 依攻擊前提、實際暴露面、權限要求、資料敏感度與影響範圍排序；嚴重度與證據信心分開記錄。不以 Top 10 排名當嚴重度，不在缺少條件時虛構 CVSS 分數。
5. **交付報告。** 使用下方格式，以繁體中文說明已確認問題、待驗證問題與覆蓋缺口。預設在回覆提供；使用者要求保存時寫入指定位置。

## 證據與操作界線

- 狀態統一使用：**發現問題、未發現問題、待驗證、不適用**。「未發現問題」僅指已檢查範圍；不適用須附理由。同類存在問題與缺口時，兩者都要列出。
- 已確認發現須有可追溯的檔案行號或執行證據，以及成立的攻擊前提與影響。只有可疑模式、套件告警或推測的部署方式時，標為待驗證並指出缺少什麼資料。
- 原始碼可證明完整攻擊路徑時可確認問題，但註明「靜態確認、未動態重現」。依賴弱點須核對解析版本、官方公告影響範圍及執行期／建置期用途；可達性未知時如實記錄。
- 報告中的密鑰、權杖與個資一律遮罩。不要將原始碼、資料庫或祕密上傳外部掃描服務。不要變更正式資料、寄送測試郵件、觸發付款或執行破壞性／壓力測試來證明風險。
- 修正納入任務時，先依專案 TDD 規範新增會失敗的回歸測試，再實作並驗證；保留既有業務規則與資料升級流程。

## 報告格式

先列整體結論、最高優先問題與限制，再提供：

- **範圍**：日期、提交或差異基準、OWASP 版本、環境、納入與排除範圍。
- **逐項覆蓋表**：類別編號與名稱、狀態、證據位置、發現編號或尚缺的驗證。十類均須有列，限定範圍外的部分明確標示。
- **發現清單**：穩定編號、標題、嚴重度（嚴重／高／中／低）、信心（高／中／低）、OWASP 類別、位置、攻擊前提、資料流與影響、重現或靜態證據、修正建議、回歸驗證方式。改善建議與已確認弱點分開列出。
- **驗證紀錄**：實際執行的命令與結果、未執行原因、後續需要的資料或測試。

OWASP Top 10 是風險分類與認知文件，不是完整驗收標準。不得將完成本技能描述成安全認證或保證沒有漏洞。需要可驗收控制或深入測試時，查閱官方 [ASVS](https://owasp.org/www-project-application-security-verification-standard/) 與 [WSTG](https://owasp.org/www-project-web-security-testing-guide/)，引用具體項目前確認其版本與識別碼。
